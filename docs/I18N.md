# Vietnamese UI (i18n)

The web client is Vietnamese by default. The engine and the server stay English. Their text (decision prompts, log
lines, FX descriptions) is data, and the web layer looks each English string up in a dictionary when it renders.
A player can switch to English in Settings → Language. The choice is kept per browser.

## What is translated, and what is not

- Translated: menus, setup, HUD, decision prompts and options, log lines, Settings, in-game menu, end screen.
- Kept in English, with a Vietnamese hover gloss: game terms (Hope, Discontent, Care, Justice, Motivation, Anger,
  Apathy, Greed, Steam Core, Generator, Meeple, Workshop, Expedition, Law, Advisor, Storm, Crater, Frozen Grove and
  others). The full list is in Settings → Game terms (Vietnamese only). Source: `tools/i18n/glossary.json`.
- Still English: card artwork and the text printed on card faces, the rulebook PDF, and player names (typed names are
  data and are shown as typed). Card ids such as `ADV_GENERATOR` are shown on card faces as printed codes.
- Laws and Expeditions tab labels stay English because both are glossary terms.

## Runtime (`apps/web/src/i18n/index.ts`)

- `useLang`: zustand store, `'vi'` by default, saved in localStorage under `frostpunk.lang` (read and written inside
  try/catch, so a blocked storage only loses the saved choice).
- `t(en)`: plain string, for attributes (`title`, `aria-label`) and anywhere a string is needed.
- `tn(en)`: visible text as a ReactNode. Glossary terms are wrapped in `<abbr class="gl-term" title="Vietnamese gloss">`.
- `setPlayerNames(names)`: called from `App.tsx` on every render, so log lines that name a player are matched.
- `glossaryEntries()`: term and gloss list for the Settings panel (capitalised terms only).
- Lookup: `t` normalises the English string into a template. Numbers become `{0}`, `{1}`, ..., and player names become
  `{P}`. The template is the dictionary key, and the numbers and names are filled back in. A key with no entry shows the
  English text. Dev builds log `[i18n] no Vietnamese text for: <key>` once per key.
- Language switch: `App.tsx` subscribes to `useLang`, sets `document.documentElement.lang`, and keys the `.app` root by
  language. `t` and `tn` read the language when they render, so the remount re-renders everything. Game state and the
  open overlay live in stores, so a switch in the middle of a game keeps the decision and the board.

## Adding or changing text

1. In the component, wrap the string: `t('Your text')` for attributes and plain strings, `tn('Your text')` for visible
   text. Keep the English literal in the code. Do not translate it in code.
2. Add `{ "key": "Your text", "vi": "..." }` to a file in `tools/i18n/ui/`. The key is the English literal with its real
   numbers, for example `"Remove 1 Wood from the map"`. The build turns the numbers into `{0}`. Do not write `{0}` in a
   `ui/` key, because the build would double it to `{{0}}`.
3. Engine-generated text goes in `tools/i18n/vi/chunk_*.json`. Its keys are already templates (`{0}`, `{P}`).
4. Run `node tools/i18n/build_vi.mjs`. It checks placeholder counts and conflicting translations, then writes
   `apps/web/src/i18n/vi.json` and `glossary.json`. It must report `problems: 0`.
5. Do not edit `vi.json` or `glossary.json` by hand. They are generated.

Style rules are in `tools/i18n/terms.md`: template placeholders, the fixed Vietnamese for common words, which terms stay
English, and short UI tone.

## Build pipeline (`tools/i18n/`, committed)

- `harvest.ts`: plays simulated games (solo and co-op, all scenarios, base and extra pack) with the bots, and collects
  every string the game shows: prompts, option labels and hints, log lines, FX descriptions and display fields of the
  raw data. Output: `tools/i18n/strings.json` (git-ignored). Run from the repo root:
  `npx tsx tools/i18n/harvest.ts 150`.
- `normalize.mjs`: `strings.json` to `templates.json` (git-ignored).
- `ui/*.json`, `vi/*.json`: the translations. `build_vi.mjs` merges them and the glossary into the web app.
- `fix_engine_tokens.mjs`: one-off repair that turned raw engine condition tokens (`active:anger`,
  `!built:fightingArena`, `toCard:supply:{0}`) into Vietnamese in the values. The keys still hold the tokens, because
  they match the engine text. It is idempotent.

`scratch/i18n/` held the working copy during translation. It is git-ignored and is not used by the build.

## Known limits

- Translations came from several agents and were reviewed, not checked by a native speaker. Wording differs in small
  places: Treat (Điều trị) and Cure (Chữa) are both used, and some event and card names may read differently in
  different screens.
- Text with no dictionary entry appears in English. Dev builds list each such key once in the console, so run a
  game in dev and read the console to find the gaps.
- The UI assumes the Vietnamese text is longer than the English. Check a new screen at 1366×768 in both languages.
